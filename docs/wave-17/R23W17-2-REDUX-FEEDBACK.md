## Architecture: Closed-Loop Scheduling

```
┌──────────────────────────────────────────────────────────┐
│                   Execute Sentrons                        │
│  (Run SIW streams on assigned cores)                      │
└─────────────────┬────────────────────────────────────────┘
                  │
                  │ Performance Metrics
                  │ (ops/cycle, cache hits, stalls)
                  v
┌──────────────────────────────────────────────────────────┐
│             SchedulerRedux::feed()                        │
│  • Store metrics history per sentron                      │
│  • Aggregate metrics per core                             │
│  • Update load/cache/stall statistics                     │
└─────────────────┬────────────────────────────────────────┘
                  │
                  │ Metrics Database
                  v
┌──────────────────────────────────────────────────────────┐
│             SchedulerRedux::decide()                      │
│  • Check load imbalance                                   │
│  • Detect cache thrashing                                 │
│  • Identify contention                                    │
│  • Generate actions (migrate/reprioritize/pair)           │
└─────────────────┬────────────────────────────────────────┘
                  │
                  │ Scheduler Actions
                  v
┌──────────────────────────────────────────────────────────┐
│               Apply Actions                               │
│  • Migrate sentron to different core                      │
│  • Adjust thread priority                                 │
│  • Pair/unpair SMT workloads                              │
└─────────────────┬────────────────────────────────────────┘
                  │
                  └─────────→ Loop back to Execute
```

## Key Types

### SentronMetrics
```rust
pub struct SentronMetrics {
    pub sentron_id: u16,
    pub ops_per_cycle: f64,
    
    // Cache performance
    pub l1_hits: u64,
    pub l1_misses: u64,
    pub cache_hit_rate: f64,

```

**Derived from ExecStats:**
- ops_retired, cycles → ops_per_cycle
- PPT hits/misses → cache hit rate
- stalls → stall rate

### CoreMetrics
```rust
pub struct CoreMetrics {
    pub core_id: usize,
    pub sentron_count: usize,
    pub total_ops: u64,
    pub ops_per_cycle: f64,
    pub avg_cache_hit_rate: f64,
    pub avg_stall_rate: f64,

```

**Aggregates across all sentrons on a core**

### SchedulerAction
```rust
pub enum SchedulerAction {
    Migrate {
        sentron_id: u16,
        from_core: usize,
        to_core: usize,
        reason: MigrationReason,
    },
    Reprioritize { sentron_id: u16, new_priority: i32 },
    Pair { sentron_a: u16, sentron_b: u16, target_core: usize },
    Unpair { sentron_a: u16, sentron_b: u16 },
}
```

**Generated by `decide()` based on observed metrics**

### MigrationReason
```rust
pub enum MigrationReason {
    LoadImbalance,   // Core overloaded
    CacheThrash,     // High miss rate
    Contention,      // High stall rate
    NumaPenalty,     // Remote memory access
}
```

## Decision Logic

### Load Imbalance Detection
```rust
// If max_load / min_load > threshold
// → Migrate sentron from busiest to least-busy core

if (max_load - min_load) / max_load > config.load_imbalance_threshold {
    migrate(busiest_core → least_busy_core)
}
```

**Default threshold:** 50% imbalance

### Cache Thrash Detection
```rust
// If cache hit rate < threshold
// → Migrate to less-contended core

if sentron.cache_hit_rate() < config.cache_hit_threshold {
    migrate(current_core → least_loaded_core)
}
```

**Default threshold:** 70% hit rate

### Contention Detection
```rust
// If stall rate > threshold
// → Migrate to less-busy core

if sentron.stall_rate() > config.stall_threshold {
    migrate(current_core → least_loaded_core)
}
```

**Default threshold:** 30% stalls

## Example Flow

### Scenario: Imbalanced Load

**Initial state:**
- 4 sentrons all on core 0
- Core 1 idle

**Round 1: Execute**
- All 4 sentrons run
- Collect metrics: ops/cycle, cache hits, stalls

**Round 1: Feed**
```rust
for sentron in sentrons {
    redux.feed(sentron.id, &exec_stats);
}
```

**Round 1: Decide**
```rust
let actions = redux.decide();
// → [Migrate { sentron: 1, from: 0, to: 1, reason: LoadImbalance }]

```

**Round 2: Execute**
- Sentron 1 now on core 1
- Load balanced: 3 on core 0, 1 on core 1

**Result:** Better resource utilization

## Philosophy

### 1. Observe, Don't Predict

**Traditional schedulers:** Predict performance based on heuristics

**Redux approach:** Measure actual performance, adapt based on reality

**Benefit:** No false assumptions, responds to actual bottlenecks

### 2. Feedback Is the Teacher

**Loop:**
1. Try assignment
2. Measure outcome
3. Learn what works
4. Adjust

**Principle:** The hardware tells us the truth through metrics

### 3. Elevation, Not Aspiration (W14)

**Aspiration:** "This assignment should give 1.89× speedup"

**Elevation:** "This assignment gave 1.2× speedup, cache hit rate is 30%, migrate to reduce contention"

**Difference:** Report reality, adapt to it
